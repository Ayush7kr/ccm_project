Frequently Asked Questions

Everything You Need to Know

Answers to common questions regarding lead assignment, call logging security, and user onboarding in CCM.

CCM enforces database unique constraints on customer phone numbers and campaign assignments. The bulk customer assignment engine checks for existing assignments before linking leads, ensuring a customer cannot be simultaneously assigned to multiple active tele-callers within the same campaign.
No. CCM implements strict object-level authorization across the database layer. Tele-caller querysets are filtered exclusively to records where `assigned_telecaller = request.user`. Attempting to access another agent's lead or live call console via direct URL manipulation results in an immediate HTTP 403 Forbidden rejection.
When a tele-caller marks a call as 'Follow-up Required' and schedules a date and time, a FollowUp record is created. Once the scheduled time elapses, CCM automatically transitions the task to 'Overdue' and alerts the caller. Tasks can be marked complete, rescheduled, or cancelled using the compact action dropdown menu.
The Report Center supports both publication-grade PDF summaries generated via ReportLab and formatted Excel (.xlsx) workbooks generated via OpenPyXL. All filters visible in the user interface (date range, campaign, tele-caller, call status) directly govern the exported files.
New callers can register directly using the public registration portal at `/register/` or be provisioned manually by an administrator. Accounts are created with encrypted PBKDF2 password hashing, receive an automated welcome notification, and immediately appear in the administrator's assignment directory.
